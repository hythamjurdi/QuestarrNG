Implemented or verified requests

- Settings, liveness/readiness, downloader priority/fallback, rate limiting,
  authentication, structured error handling, discovery, indexer tests, and
  download status/details are present in the routes, pages, and tests cited in
  the ledger.
- The older health-check request (#30, #50, PR #61) is covered by public
  liveness `/api/health` and readiness `/api/ready` probes. The readiness probe
  checks database and IGDB connectivity and returns a status-only body; later
  upstream hardening split these probes to avoid exposing component details.
- Discovery formatting still uses a null status to mean “not in the library,”
  but the POST `/api/games` server schema transforms a missing or null status
  to `wanted` before storage. This resolves the persistence concern in #35
  without marking untracked discovery results as wanted. The API regression
  test in server/__tests__/api_routes.test.ts verifies the null-status request.
- IGDB searches already cap phrase/word-search attempts at five. They now retry
  transient 429 and 5xx responses for at most three requests total, honor a
  bounded Retry-After value, and use capped exponential backoff otherwise.
  Routine fallback/result logs now use debug level. A regression test covers
  429, 5xx, Retry-After, backoff, and the three-request cap.
- The PostCSS/Vite warning fix from issue #48 and PR #101 is present as an
  explicit `css.postcss.from: undefined` setting in `vite.config.ts`.
- PR #65’s AddGame field filtering, PR #67’s `{ error, details? }` handling,
  PR #68’s tests, and PR #69’s removal of direct Neon/`ws` dependencies are
  present in current source and manifests.
