## Real PostgreSQL smoke check

A disposable PostgreSQL **18.6** cluster was initialized under a unique local
`/tmp` directory on host `kspld0` and bound to `127.0.0.1:55432`. The production
`node-postgres` driver connected, applied fresh migrations, reapplied migrations
idempotently, and passed its database ping. A storage-level setup-user insert
then succeeded. Two concurrent API-key creation requests against a one-key cap
produced exactly one success and one rejection, with one key persisted. This
exercises the real connection pool and transaction locks that in-process PGlite
cannot model. No service on the host's PostgreSQL port was contacted.

## Scratch and cleanup

Local `/tmp` on `kspld0` had 52 GB available before the smoke check; no NFS
scratch was needed. The disposable cluster was stopped, port 55432 was verified
free, and its database files and one-off smoke script were removed. Docker and
the running host PostgreSQL services were left untouched.
