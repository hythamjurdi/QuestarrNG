## Changes

The recovery CLI now uses the exact `passwordPolicySchema` shared by account
setup and password changes. It trims before validation and hashing, never
accepts a password as a command-line argument, rejects a failed storage update,
and keeps raw password or storage/hash errors out of logs. Its orchestration is
dependency-injected so the policy and persistence outcomes can be tested
without touching a real account database.

The API, security assessment, README, deployment documentation, and navigation
now explain the account-recovery workflow and its operator-only host/container
boundary. The API reference also documents the 403 ownership responses for
game status and visibility changes. No files under `client/src/**` changed, so
the visual-evidence requirement did not apply.
